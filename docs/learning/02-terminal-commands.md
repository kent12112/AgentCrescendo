# Terminal commands used in the first slice

Learning preference: explain commands before running them, including their purpose, key flags/operators, expected output, and state changes. Follow with what the output means. Use concise reminders for commands already explained.

## Navigation and inspection

| Command | Meaning |
|---|---|
| `pwd` | Print the current working directory. Relative paths start here. |
| `ls -la` | List files; `-l` includes details and `-a` includes hidden names such as `.env`. |
| `df -h .` | Show free space on the filesystem containing this directory; `-h` uses readable units. |
| `rg --files` | List searchable file paths using ripgrep. Hidden/ignored files are excluded by default. |
| `rg -n 'pattern' file` | Find matching text; `-n` prints line numbers. |
| `tail -n 20 file` | Read the last 20 lines, useful for recent log entries. Read-only, but log output may contain private data. |
| `ps -axo pid,comm` | List processes with IDs and executable names: `-a` includes other users' terminal processes, `-x` includes processes without a terminal, and `-o` chooses columns. |

## Project environment

`python3.11 -m venv .venv` runs Python's `venv` module and creates an isolated dependency environment. `source .venv/bin/activate` changes the current shell so `python` and installed tools resolve to that environment. Alternatively, `.venv/bin/python` explicitly selects it without activation.

`pip install -r requirements-dev.lock` installs the dependency versions in a file. `pip install --no-deps -e .` links the local project in editable mode (`-e`), without reinstalling dependencies (`--no-deps`). These commands modify the active Python environment.

`npm install` installs the dashboard dependencies. With an existing lockfile, `npm ci` is preferable for a clean, reproducible installation; it replaces the existing `node_modules` directory and requires the manifest and lockfile to agree.

`npm run build` invokes the `build` script in `package.json`. It creates production output in `.next`; it does not publish the app.

## Database and API

`docker compose up -d --wait db` starts the `db` service from `compose.yaml`. `-d` runs it in the background; `--wait` waits for readiness, using the health check where configured. It can download an image and create a container, network, and persistent volume.

`docker compose ps` reports service status. `docker compose stop db` stops the database while preserving its data. `docker compose down -v` removes the project's volumes as well as containers; do not use it casually because those volumes hold saved drafts.

`alembic upgrade head` applies migrations through the latest revision and changes the database schema. `alembic check` checks whether model changes would require an additional autogenerated migration; it does not prove application correctness.

`uvicorn crescendo_api.main:app --host 127.0.0.1 --port 8000` serves the FastAPI object `app` from module `crescendo_api.main` on the local loopback address. It stays in the foreground until stopped. `--reload` optionally restarts development processes when source changes.

`Ctrl+C` sends SIGINT to the foreground process group. It normally asks a server to shut down cleanly. It does not delete database contents.

## HTTP and shell syntax

`curl --max-time 5 --silent --show-error URL` makes an HTTP request. `--max-time 5` caps the request duration, `--silent` hides the progress meter, and `--show-error` still displays failures. A timeout means no completed response within the limit; it alone does not establish why.

`command_a && command_b` runs the second command only when the first exits successfully. `command_a | command_b` pipes the first command's standard output into the second command's standard input. `>` redirects standard output to a file and replaces existing contents; `>>` appends instead.

`.venv/bin/python - <<'PY'` starts a heredoc: Python reads a script from standard input until a line containing only `PY`. Quoting the delimiter prevents shell expansion inside the script, which is especially important around `$` and backticks.

`git diff --check` looks for whitespace errors and conflict markers in changes; it is not a test suite. `git status --short` shows changed/untracked files without modifying them.

## Docker recovery observed in this session

Docker's engine socket timed out while one backend process remained stuck. A graceful SIGTERM shutdown closed its UI and worker processes, but the backend ignored it. After checking the exact process identity, SIGKILL terminated only that remaining backend; Docker then relaunched successfully and reported engine version 27.3.1.

SIGKILL is a last resort: it cannot be handled for cleanup and can interrupt workloads. No Docker reset or data deletion was performed. A running UI process does not prove a visible window, and a visible window does not prove the engine is healthy.

The PostgreSQL migration and schema check passed. A draft was created through Next.js → FastAPI → PostgreSQL, retrieved, and retrieved again after the API process restarted. The integration test also exposed and fixed a legitimate-origin rejection caused by Next.js normalizing its internal request hostname. Cross-origin and missing-origin writes remained rejected after the fix.
